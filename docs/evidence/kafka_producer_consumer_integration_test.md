**Test date:** 12 November 2026

**Component owner:** Aditya Singh Bisht

**Component:** Python IoT Simulator and Apache Kafka

**Environment:** Windows, Docker Desktop, Apache Kafka 4.4.0, Python 3.12.16

**Kafka topic:** `container_sensor_telemetry`

**Test status:** PASS

## 1. Objective

The objective was to verify end-to-end integration between the AtmoSync IoT simulator, Kafka producer and Kafka consumer.

The test checks whether telemetry events generated by the simulator are validated, published to Kafka, retrieved by the Python consumer, and processed successfully.

## 3. Test Procedure

1. Started the Python Kafka consumer using a fresh consumer group and `latest` offset configuration.
2. Allowed the consumer to initialize before starting the simulator.
3. Started the IoT simulator in a separate terminal.
4. Verified that the simulator generated telemetry events for the five configured containers.
5. Verified that each event passed the project's data validator.
6. Confirmed successful Kafka publishing, including partition and offset metadata.
7. Compared the events received by the consumer against the events published by the simulator.
8. Verified the consumer's final processing and rejection counts.

## 9. Limitations and Remaining Work

1. This test used a bounded consumer run of five messages. Continuous consumer operation remains available through the existing `max_messages=None` configuration but was not separately demonstrated in this test.
2. The simulator is configured for continuous publishing; the test does not establish production-scale throughput.
3. The test used one Kafka broker, one partition and replication factor 1.
4. The test confirms successful event delivery and processing, not exactly-once processing.
5. A dead-letter queue for malformed messages has not yet been implemented.
6. Producer behaviour during a broker outage has not been established by this integration test.
